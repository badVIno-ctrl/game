# Командный режим (5×5) — что внутри

## Поток для игрока

1. На главной — карточка **«ИГРА КОМАНДАМИ»**.
2. Вводит ник → жмёт «Войти».
3. Сервер делает **одно из двух**:
   - **Идёт активный матч с местами** → игрока **молча подсасывает прямо в бой** в команду с меньшим числом людей (`late_join=true`). Существующие игроки получают `team_room_state` с обновлённым ростером и видят нового персонажа на карте, плюс уведомление «ИГРОК <ник> ПОДКЛЮЧИЛСЯ К КОМАНДЕ».
   - **Нет активных матчей** → попадает в **командное лобби**. Видит обе команды живьём. Кнопка «Старт» активируется, когда в каждой команде хотя бы 1 человек.
4. После старта — респаун у своего щита экипировки, AKM/M416/броня/шлем выдаются автоматически.
5. Убили? Респаун через 5 секунд на одном из 5 спавнов команды.

## Карта

- Тот же мир, **растянут в 1.5×** (плей-зона теперь от z=+22 до z=-228, ~250 единиц вместо 160).
- 9 декоративных домов (было 4) разнесены по двум маршрутам наступления.
- 21 сэндбэг-кластер, 18 ящичных пирамид, 6 дополнительных траншей в центре карты.
- 5 точек спавна на каждую команду: команда A — у южного щита, команда B — у северного зеркального щита.
- Спавны разнесены по X на ±6 единиц, чтобы команда не телепортировалась стопкой в одну точку.

## Сетевая часть

| Событие | Кто шлёт | Кому | Что делает |
|---|---|---|---|
| `team_join` | клиент | сервер | подключение к лобби ИЛИ late-join в активный матч |
| `team_lobby_state` | сервер | лобби | живой список двух команд |
| `team_start` | клиент | сервер | старт матча (нужно ≥1 в каждой) |
| `team_match_start` | сервер | клиенту | редирект в `/game?mode=team&room=…` |
| `team_join_room` | клиент | сервер | хендшейк после загрузки игровой страницы |
| `team_game_start` | сервер | клиенту | загрузка ростера, авто-экипировка, старт стейта |
| `team_state` | клиент | сервер (15 Hz) | позиция + ориентация + здоровье |
| `team_player_state` | сервер | другим | трансляция чужого стейта |
| `team_shot` / `team_player_shot` | оба | оба | звук + трассер + муз-флэш |
| `team_hit` | клиент | сервер | «я попал в <ник>» — **сервер фильтрует френдли-фаер** |
| `team_took_damage` | сервер | жертве | прилетел урон |
| `team_died` | клиент | сервер | «меня убили» — сервер начисляет +1 убийце (**если он из другой команды**) |
| `team_round_over` | сервер | всем | обновление лидерборда + триггер респауна |
| `team_respawn` | сервер | мёртвому | новый спавн через 5 секунд |
| `team_grenade` / `team_player_grenade` | оба | оба | бросок/детонация гранат |
| `team_room_state` | сервер | всем | снапшот ростера (late-join, выход, обновление килов) |
| `team_player_left` | сервер | всем | игрок вышел — клиент удаляет аватар |

## Бан френдли-фаера

- На сервере: при `team_hit` проверяется `team_of[target] != team_of[shooter]`, иначе **бросаем урон в ноль**.
- На сервере: при `team_died` начисление кила только если `team_of[killer] != team_of[killed]`.
- На клиенте: ник союзника подсвечен **зелёным**, врага — **красным**. Так что прицеливание подсказывает «свой/чужой».

## Фикс бага со счётом

**Что было:** при убийстве иногда давало +2 или +3 очка вместо +1.

**Почему:** когда здоровье жертвы переваливало через 0, клиент вызывал `pvpSend('died')`, но `controls.unlock()` выполняется **асинхронно**. До того, как `controls.isLocked` стало `false`, успевали прилететь ещё 1–2 пакета `took_damage`, каждый из которых повторно дёргал `handleDeath()` → ещё `pvpSend('died')`. На сервере не было идемпотентности: каждый `died` накручивал +1.

**Что починили:**
- Клиент: флажок `_pvpDying` / `_teamDying`. Как только отправили один `died`/`team_died`, второй раз не шлём до `respawn`.
- Сервер 1×1: `room.round_active` устанавливается в `False` при первом `died`; следующие игнорируются. Сбрасывается обратно в `True` на респауне.
- Сервер 5×5: `team_room.dying` — set ников, которых уже зачли мёртвыми. Пока ник в этом сете, повторные `team_died` от него не дают очки. Сбрасывается на респауне.
- Сервер: даже при правильно сработавшем клиенте, +1 даётся **только если убийца из другой команды и есть в `scores`**. То есть случайный baseHit от себя самого или от союзника не накрутит счёт.

## Тесты

Все запускаются после `python3 main.py`.

- `tests/test_e2e.py` — 31 кейс: базовый поток лобби, авто-баланс, anti-friendly-fire, фикс счёта в обоих режимах, late-join, отказ старта при пустой команде.
- `tests/test_edge.py` — 17 кейсов: рассылка `team_room_state` при late-join, заполнение 10 слотов, выход игрока в матче, реконнект под тем же ником, гонка двух одновременных `team_start`.

**Результат:** 48 / 48 PASS.

## Что я ещё бы прикрутил (предложения)

Эти штуки в этой итерации **не делал**, потому что они не входили в твой ТЗ, но они логично продолжают сделанное:

### Геймплей

1. **Голос-командочат на пробел вне выстрела** — заранее заготовленные команды («Враг по центру», «Прикрой», «Стою на пойнте») с радиальным меню, как в R6S. Текстовый чат тоже, но он отвлекает в шутере.
2. **Раунды до N убийств / тайм-лимит** — сейчас матч бесконечный. Сделать «первый до 50 очков», или «лучшие 2 из 3 раундов с переходом сторон через пол-карты».
3. **Точки захвата (CTF / Hardpoint)** — у вас уже есть CTF-логика в боте-режиме. Команда удерживает A/B/C 30 секунд → плюс командные очки. Стимулирует не отсиживаться на споне.
4. **Класс/лоадаут** — штурмовик (M416), снайпер (с прицелом 3×), штурмовик с обрезом, медик (бандаж быстрее, +50 hp реген). На спауне выбираешь раз в раунд.
5. **Карта мини-карты в HUD** — точки союзников, последняя позиция врага (3 секунды после выстрела). У вас уже есть миникарта в боте-режиме, перенести легко.
6. **Killcam на 2 секунды** — фиксированная камера, смотрящая глазами того, кто тебя убил. Снижает фрустрацию «откуда меня убили».

### Сеть / устойчивость

7. **Reconnect в тот же матч** — если ник был в комнате, ws отвалился, повторное `team_join` с тем же ником → автоматически возвращается в свою команду, со своим счётом, на свой спавн. Сейчас уже работает на 90%, докрутить пару строк.
8. **Региональные серверы** — Render бесплатный засыпает через 15 минут. Для шутера это смерть. Минимум — Cloud Run / Fly в Европе с холодным стартом ≤500 мс, или платный Render Starter ($7/мес), чтобы не засыпал.
9. **Лаг-компенсация (rewind)** — сейчас сервер слепо доверяет клиенту: «я попал в Х». При пинге 80мс это даёт стрелявшему преимущество. Делается так: сервер хранит позиции игроков за последние 200 мс и при `team_hit` откатывает мир к моменту выстрела shooterа, проверяет рейкаст уже у себя.
10. **Анти-чит-санити-чек** — урон/секунда лимит, скорость передвижения лимит, отказ от выстрелов сквозь стены (рейкаст у сервера). Без этого один умник на питон-скрипте сольёт лобби.

### Контент

11. **Звуковой пинг по выстрелам** — стрельба слышна на расстоянии (у вас уже есть в боте), но без отображения на карте. Добавить точку на миникарте на 1.5 секунды.
12. **Распределение убийств по типам урона** — статистика после раунда: хедшоты, дальние выстрелы, кросс-кидания.
13. **MVP раунда** — в конце раунда крупная плашка с лучшим игроком. Чисто dopamine.
14. **Командные эмодзи / надписи над спавном** — типа «GG», «WP», «:-)». Маленькая штука, но усиливает чувство команды.

### UX лобби

15. **Чат в лобби** — пока ждёшь начала, можно потрепаться. 30 строк, 10-секундный rate-limit, без модерации.
16. **«Реди»-кнопка вместо «Старт»** — каждый отмечает «готов», старт срабатывает автоматически когда все готовы (или таймер 30с после готовности первого). Иначе вечно один торопит другого.
17. **Spectator mode** — войти в активную игру не как игрок, а как наблюдатель. Прыгает между POV игроков. Полезно для стримов / разбора.
